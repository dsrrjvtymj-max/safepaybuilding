Infrastructure & Hosting

What it takes to run SafePay Building

The How It's Built page covers the money flow through Mangopay. This page is the technical blueprint underneath it: the databases that hold project and ledger data, the application services, and the hosting, security and monitoring tools that keep the platform online. SafePay Building never stores card numbers or wallet balances itself — those live inside Mangopay — so this stack is deliberately lean.

Databases

One relational database is the system of record for everything SafePay Building owns. The other stores are supporting infrastructure — cache, files, logs and search — each chosen because Postgres alone would be the wrong tool for that job.

Store What it holds Why it's separate
PostgreSQLAmazon RDS / Neon Users and roles, businesses, projects, milestones, milestone evidence metadata, disputes and messages, the internal transaction ledger, and every Mangopay reference ID (user, wallet, pay-in, transfer, payout). Primary system of record. Relational integrity and transactions matter — a milestone release touches several rows at once and must be all-or-nothing.
RedisElastiCache / Upstash Login sessions, API rate-limit counters, short-lived caches of dashboard data, and the background job queue (BullMQ). In-memory speed for data that is ephemeral or changes by the second. Keeping it out of Postgres protects the primary DB from load.
Object storageAmazon S3 Progress photos, inspection reports, signed contracts, lien waivers, dispute evidence uploads. Binary files don't belong in a relational DB. S3 gives cheap, durable storage with per-file access control; Postgres just stores the key and metadata.
Audit logAppend-only table / QLDB An immutable record of every state change: who approved a milestone, when funds moved, every admin action, every webhook received. Financial dispute resolution and compliance need a tamper-evident history that is never updated or deleted — different guarantees from normal tables.
Search indexOpenSearch Denormalised copies of projects, contractors and transactions for fast full-text and faceted search in dashboards and admin tools. Full-text search and aggregations across large tables are slow in Postgres; the index is rebuilt from Postgres and is disposable.
Data warehouseBigQuery / Snowflake — optional Historical snapshots for finance reporting, cohort analysis and regulatory returns. Heavy analytical queries should never run against the production database. Loaded nightly via ETL.

Hosting & operational tooling

The platform is designed to run on managed services so a small team can operate it. Everything below is deployed from Git — no manual server changes.

Layer Tool Purpose
DNS / CDN / WAF Cloudflare Domain, TLS certificates, global caching, web application firewall, bot protection and DDoS mitigation.
Frontend host Vercel or Netlify (alt: S3 + CloudFront) Serves the static marketing site and the compiled dashboard SPA, with preview deploys per pull request.
Application runtime AWS ECS Fargate (alt: Render, Fly.io) Runs the API, workers and scheduler as containers with autoscaling and no server patching.
Container registry Amazon ECR Stores the Docker images built by CI.
Managed Postgres Amazon RDS (alt: Neon, Supabase) Automated backups, point-in-time restore, read replicas, encryption at rest.
Managed Redis Amazon ElastiCache (alt: Upstash) Cache and queue backend, replicated for failover.
CI/CD GitHub Actions Runs tests, builds images, applies database migrations, deploys on merge to main.
Infrastructure as code Terraform Every AWS resource above is defined in version-controlled config.
Secrets AWS Secrets Manager Mangopay API keys, database credentials, webhook signing secrets — injected at runtime, never in Git.
Observability Grafana Cloud / Datadog + Sentry Metrics, dashboards, log aggregation, uptime alerts and application error tracking.
Transactional messaging Postmark (email) + Twilio (SMS) Milestone notifications, approval requests, payout confirmations, 2FA codes.

Environments & data protection

Three isolated environments — development, staging and production — each with its own database and its own Mangopay sandbox or live credentials. Key controls:

Concern Approach
PCI scope Minimised — card data is entered into Mangopay-hosted fields and never transits SafePay servers, so the platform stays SAQ-A.
Encryption TLS 1.2+ in transit everywhere; AES-256 at rest on RDS, S3 and backups.
Backups Automated daily Postgres snapshots with 35-day point-in-time recovery; S3 versioning with lifecycle rules.
Access Least-privilege IAM roles, SSO for the team, no shared logins, all production access audited.
Data residency All stores hosted in a UK / EU region to match Mangopay and UK GDPR.
Retention Project and ledger records kept for the statutory period; personal data erasable on request except where financial-record law requires retention.

Reference: Mangopay documentation — wallets, KYC, webhooks and payout timings. Tool names are illustrative of a typical managed-services stack; alternatives are noted where relevant.
